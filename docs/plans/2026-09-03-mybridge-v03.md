# MyBridge V0.3 Auto Folder Mirror Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 MyBridge 从单个 Source/Destination 配置升级为多个 Windows Folder Mirror，让 Mac 自动把每个 Windows 项目目录映射到 `~/MyBridge/<mirror-name>`，并在重连后自动补齐。

**Architecture:** 保留现有 UDP discovery、HTTP pairing/token、流式 PUT、临时文件原子替换和 `fs.watch`。新增 `mirrors[]` 配置；源端为每个启用的镜像创建一个 `SyncEngine`，上传请求携带 `mirrorId`，Mac 端在配对后注册镜像并按安全的 `targetFolderName` 路由到 `mybridgeRoot` 下的目录。旧的单目录字段和 API 保留为兼容路径，不参与新的默认 UI 流程。

**Tech Stack:** Node.js 22、Electron 现有桌面壳、Node 标准库 `fs/http/dgram`、本地 JSON、原生 `node:test`，不新增同步协议依赖、数据库或服务端。

---

## Current V0.1/V0.2 Model

- `ConfigStore` 只有 `sourceFolder`、`destinationFolder`、`pairedDevice` 和 `pairedSource`。
- `Agent` 只有一个 `SyncEngine`；`FileReceiver` 总是把文件写入一个 `destinationFolder`。
- `SyncEngine.syncAll()` 已支持递归扫描、稳定性等待和 watcher 增量同步；`FileReceiver` 已支持路径校验、流式临时文件和原子替换。
- 当前 V0.2 的 pause、recovery、tray 和 Electron 生命周期继续复用。

## V0.3 Model

```text
config.json
├── mybridgeRoot
├── ignoreRules[]
├── mirrors[]
│   ├── id
│   ├── name
│   ├── sourceDeviceId
│   ├── sourcePath
│   ├── targetDeviceId
│   ├── targetDeviceName
│   ├── targetFolderName
│   └── enabled
├── pairedDevice / pairedSource
└── legacy sourceFolder / destinationFolder
```

运行态额外提供每个镜像的 `status`、`lastSyncAt`、`currentFile`、`fileCount`、`pendingCount`，这些状态用于 UI，不引入数据库。`ignoreRules` 为所有镜像共享的简单规则，默认忽略 `.git`、`node_modules`、`.DS_Store`、临时文件、cache、log 和 MyBridge 临时文件。

## Safety and Scope Constraints

- Only source-to-target upload remains supported; no delete propagation, bidirectional writes, conflict resolution, public-network transport or accounts.
- Removing a mirror removes only its relationship and watcher; it never deletes source or target files.
- `targetFolderName`, mirror IDs and relative file paths are validated before filesystem access.
- A remote registration failure leaves the local mirror configured and retries after discovery/recovery; it must not crash the Agent.
- Each milestone ends with focused tests before moving to the next one.
